# ADR-0005: fast-xml-parser v5 への移行で、エンティティのデコード挙動の変化を受け入れる

- **ステータス**: Accepted
- **日付**: 2026-09-13

## 背景

TypeScript の reader が使う fast-xml-parser 3.17.6 には未修正の脆弱性が 2 件あり
(`GHSA-x3cc-x39p-42qx`、`GHSA-gh4j-gqv2-49f6`)、修正版は 5.7.0 以降にしかない。
メジャーをまたぐ移行が避けられない。

移行にあたり、実際の ONIX ファイル (`fixtures/20201200.onix`) で v3 と v5 の出力を
比較したところ、`ignoreDeclaration` を付ければバイト単位で一致した。当初はこれを根拠に
「挙動は変わらない」と説明した。**これは誤りだった。**

レビューで指摘されたのは、この fixture に**エンティティ参照が 1 つも含まれていない**
ことである (`&` はすべて CDATA の内側にある)。つまり一致は、差が出る条件を
入力が満たしていなかったから成立していたにすぎない。

差は明確に存在する。

```js
const xml = '<r><t>Marks &amp; Spencer</t><?pi go?></r>';

v3            // {"r":{"t":"Marks &amp; Spencer"}}
v5 (既定)      // {"r":{"t":"Marks & Spencer","?pi":""}}
```

1. **エンティティ参照**: v3 は `&amp;` を展開せず、文字列としてそのまま返す。
   v5 は `&` にデコードする (`processEntities` の既定が true)。
2. **処理命令**: v5 は XML 宣言以外の処理命令も `?name` というキーで返す。

ONIX の実データでは、書名や著者略歴に `&amp;` が日常的に現れる。したがって 1 は
「理論上あり得る差」ではなく、**利用者が確実に踏む差**である。

## 決定

**v5 の挙動を受け入れる。** `processEntities: false` を指定して v3 の挙動を再現することは
しない。

そのうえで、処理命令については `ignorePiTags: true` を追加して抑制する。
`ignoreDeclaration` だけでは XML 宣言しか抑えられない。

```ts
const parser = new XMLParser({ ignoreDeclaration: true, ignorePiTags: true });
```

## 理由

v3 の挙動は仕様として正しくない。XML において `&amp;` は `&` を表すエスケープであり、
パーサがそれを展開せずに返すのは、利用者に二重デコードを強いるということである。
v5 はこれを直した。

後方互換性を守る、という原則はこのリポジトリの中心にあるが、それは
「間違った出力を永続させる」ことを意味しない。ここで `processEntities: false` を
指定すれば差分は消えるが、それは脆弱性の修正だけを取り込んで、同じリリースに含まれる
バグ修正を明示的に打ち消す、という選択になる。生成物の利用者にとって、
`"Marks &amp; Spencer"` という文字列が返り続けることに価値はない。

ただし**黙って変えてよい話ではない**ので、この ADR と PR で明示する。
なお TypeScript のサポートは README 上まだ "Not yet" の段階であり、
既存利用者への影響が限定的であることも判断を後押しした。

## 検討した他の選択肢

- **`processEntities: false` を指定して v3 と完全一致させる**: 差分はゼロになるが、
  上記のとおりバグの温存になる。将来「なぜエンティティが展開されないのか」を
  誰かが再調査することになる。**採らない。**
- **移行せず 3.17.6 に留まる**: 脆弱性 2 件が残る。**採らない。**

## 結果

- 生成される TypeScript reader の出力は、エンティティ参照を含む入力に対して
  これまでと変わる。展開後の文字列が返る。
- 数値の解釈にも細かな差がある。17 桁以上の数値は v3 が精度を落とした `number`、
  v5 は `string` を返す。ISBN-13 / GTIN-13 は 13 桁なので影響しない。
- **既知の未解決問題** (この移行とは独立、v3 でも同じ): `"01"` のような先頭ゼロの
  ONIX コードは、v3 / v5 のいずれでも数値 `1` に変換される。コード値が壊れているため
  本来は `parseTagValue: false` 相当の対処が要るが、挙動としては移行前後で同一なので
  この ADR の範囲外とする。別途対応する。
- TypeScript の reader は CI で一切実行されていない。この ADR が記録している比較は
  手作業の一度きりの確認であり、回帰を検出する仕組みは無い。
